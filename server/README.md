# 중계 서버

플레이어끼리 직접 연결하지 않도록 메시지를 대신 전달합니다.
게임 파일도 함께 내려주므로, 이 서버 하나만 띄우면 됩니다.

## 실행

```bash
cd server
npm install
npm start
```

띄운 뒤 브라우저에서 **http://localhost:3000** 을 엽니다.
같은 주소에서 게임을 받았으면 중계 서버 주소는 **자동으로 잡힙니다** — 입력할 필요가 없습니다.

같은 집(공유기) 안의 다른 컴퓨터에서 붙으려면 `http://<내 로컬 IP>:3000` 으로 접속하면 됩니다.

## 설정

환경 변수로 바꿉니다.

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `PORT` | 3000 | 포트 |
| `MAX_ROOMS` | 200 | 동시에 열 수 있는 방 수 |
| `MAX_PEERS` | 8 | 한 방의 최대 인원 |

```bash
PORT=8080 MAX_PEERS=6 npm start
```

## 하는 일 / 하지 않는 일

**합니다**
- 방을 만들고 같은 코드끼리 묶습니다.
- 메시지를 방 안의 나머지에게 전달합니다. 받는 사람이 정해진 메시지(`hit`·`st`)는 그 사람에게만 갑니다.
- **신원을 강제합니다.** 클라이언트가 `id`·`from` 에 뭐라고 적든 서버가 아는 값으로 덮어씁니다.
  남인 척하기는 이것으로 막힙니다.
- 속도 제한(초당 200개), 메시지 크기 제한(4KB), 방 코드 검사, 죽은 연결 정리.
- 게임 파일 서빙 (`server/` 폴더와 상위 폴더 밖은 내주지 않습니다).

**하지 않습니다 — 중요**
- **게임 판정을 하지 않습니다.** 위치·명중·피해는 여전히 클라이언트가 정하고 서버는 옮기기만 합니다.
- 따라서 **치팅을 막지 못합니다.** 콘솔을 열 줄 아는 사람은 여전히 무적이 되거나 한 방에 죽일 수 있습니다.
  피해값 상한(250)은 터무니없는 숫자를 거르는 안전장치일 뿐, 방어가 아닙니다.

치팅을 막으려면 서버가 물리와 판정을 직접 굴려야 합니다(**서버 권위 구조**).
그러려면 충돌·물리 코드와 맵을 서버와 클라이언트가 함께 쓰도록 떼어내야 합니다.

## 인터넷에 올릴 때

`https://` 페이지에서는 `ws://` 로 연결할 수 없습니다. **TLS 인증서가 필요합니다.**
보통은 Caddy·nginx 를 앞에 두고 `wss://` 로 받습니다. Caddy 예:

```
내도메인.com {
  reverse_proxy localhost:3000
}
```

Caddy 는 인증서를 알아서 받아 갱신하므로 `wss://내도메인.com` 이 바로 됩니다.

올릴 곳은 작은 VPS 면 충분합니다 — 이 정도 게임이면 고정 요금이 예측 가능해서 낫습니다.
